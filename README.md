شار# مراقب أسعار مكعب (Mokab Price Tracker)

مشروع **منفصل تماماً** عن مشروع تحليل مراجعات فروع مكعب على Google Maps (ذاك في مستودع `Mokab_review`). هذا المستودع غرضه الوحيد: مراقبة أسعار ومنتجات mokab.com والتنبيه عند أي تغيير.

## الهدف

مراقبة يومية لـ **كامل كتالوج منتجات mokab.com** (حوالي 5000 منتج) — لم يعد التركيز على 6 فئات محددة فقط، بل كل منتج موجود في خريطة الموقع (sitemap) الخاصة بمكعب.

## البنية التقنية (لماذا هذا التصميم بالذات)

- **لا يوجد Apify ولا مهمة Claude مجدولة** — جرّبنا ذلك أولاً لكنه يكلّف (Apify compute units) ويعتمد على فتح تطبيق Claude. استبدلناه بالكامل بـ **GitHub Actions** لأنه مجاني ومستقل عن أي جهاز/تطبيق.
- **الاكتشاف عبر sitemap.xml** — السكربت يجيب `https://mokab.com/sitemap.xml` (فهرس)، يتجاهل أي خريطة فرعية تخص المدونة (blog)، ويجمع كل رابط منتج (أي رابط بصيغة `.../p<رقم>`) من باقي الخرائط الفرعية. هذا يغطي كامل الكتالوج تلقائياً (~4999 رابط منتج حالياً)، ولا يحتاج تحديث يدوي لو مكعب أضاف/أزال منتجات مستقبلاً.
- **لا حاجة لـ Playwright إطلاقاً الآن** — اكتشفنا أن صفحة كل منتج على حدة (بعكس صفحات التصنيفات/الفئات) تضمّن السعر والتوفر والاسم كـ **meta tags من نوع Open Graph/Product** (`product:sale_price:amount`, `product:price:amount`, `product:availability`, `og:title`) مباشرة في HTML الخام. يعني طلب HTTP عادي بمكتبة `requests` كافٍ لكل الكتالوج — تم إزالة Playwright بالكامل من المشروع (لا تثبيت متصفح، لا تشغيل جافاسكربت).
- **فحص متوازٍ محدود** — يستخدم `ThreadPoolExecutor` بعدد اتصالات متزامنة معتدل (8) لتغطية ~5000 منتج خلال وقت معقول دون إثقال سيرفر مكعب أو التسبب بحظر، مع إعادة محاولة بسيطة (مرتين) لأي صفحة تفشل.
- **حماية من الإنذارات الكاذبة** — لو نسبة فشل قراءة المنتجات أعلى من 50% (أو صفر منتجات كلياً)، على الأغلب حظر مؤقت أو عطل من مكعب، فالسكربت يتوقف بخطأ واضح في الـ Actions log **بدون** فتح Issue وبدون تحديث baseline ببيانات غير موثوقة.
- **دفع baseline المحدَّث لـ GitHub بأمان** — خطوة الـ commit تعمل `fetch` + `rebase` على `origin/main` قبل الـ `push` (مع إعادة محاولة حتى 5 مرات)، لتفادي فشل `non-fast-forward` إذا صار push آخر على `main` أثناء تشغيل الفحص (قد يستغرق دقائق نظراً لحجم الكتالوج).
- **مهلة تشغيل أطول** — الـ workflow يحدد `timeout-minutes: 90` نظراً لحجم الفحص (~5000 صفحة).
- **التنبيه عبر GitHub Issues** — عند اكتشاف أي تغيير، يُفتح Issue في هذا المستودع، وGitHub يرسل بريد تلقائي (بدون أي إعداد SMTP أو أسرار إضافية). **لا يوجد تيليجرام حالياً** (تم استبعاده بطلب المستخدم).

## الملفات

| الملف | الوظيفة |
|---|---|
| `check_prices.py` | السكربت الرئيسي: يكتشف كل روابط المنتجات من sitemap.xml، يجيب كل صفحة منتج بطلب HTTP عادي ويستخرج السعر/التوفر/الاسم من meta tags، يقارن بخط الأساس، يبني تقرير التغييرات بجدولين |
| `mokab_price_baseline.json` | "الذاكرة" — آخر حالة معروفة لكل منتج (productID → الاسم، السعر، العملة، التوفر، الرابط). يتحدّث تلقائياً بعد كل تشغيل ناجح؛ سيكبر تدريجياً حتى يشمل كل الكتالوج |
| `.github/workflows/price-check.yml` | يشغّل السكربت يومياً 6:00 صباحاً بتوقيت السعودية (`0 3 * * *` UTC) وعند الطلب اليدوي، بدون تثبيت Playwright، بمهلة 90 دقيقة، ويفتح Issue إذا لزم |

## صيغة التقرير الحالية (بطلب المستخدم — جدولان فقط، بسيطة وواضحة، لم تتغيّر مع التوسّع لكامل الكتالوج)

الـ Issue اليومي (لو فيه تغييرات) يحتوي **جدولين فقط**، لا فقرات نصية:

1. **💰 المنتجات اللي تغيّر سعرها** — جدول: المنتج | السعر القديم | السعر الجديد | نسبة التغيّر | الرابط. المنتجات اللي سعرها ثابت **لا تُذكر إطلاقاً**.
2. **🆕 منتجات جديدة** — جدول: المنتج | السعر | الرابط.

لا يوجد حالياً تتبّع لتغيّر الخصم/العرض، أو حالة التوفر بشكل منفصل، أو "منتج اختفى" — تم حذفها بطلب المستخدم لتبسيط التقرير (كانت موجودة بنسخة سابقة قبل التوسّع لكامل الكتالوج).

## كيف تُشغّله يدوياً للتأكد

تبويب **Actions** في المستودع ← **Mokab Price Check** ← زر **Run workflow**.

نظراً لحجم الكتالوج (~5000 منتج)، التشغيل قد يستغرق عدة دقائق إلى أكثر من ساعة حسب سرعة استجابة مكعب — راقب الـ log لرؤية تقدّم الفحص (يُطبع كل 500 منتج).

## إذا احتجت لاحقاً (أفكار جاهزة لم تُفعّل بعد)

- ربط بتيليجرام (بوت + chat_id كـ GitHub Secrets) بدل/بجانب GitHub Issues
- إعادة تفعيل تتبّع الخصم/التوفر/الاختفاء إذا احتاجها المستخدم لاحقاً (كانت موجودة، أُزيلت لتبسيط التقرير)
- رسم بياني لتاريخ السعر عبر الزمن (يحتاج تخزين تاريخي وليس فقط آخر قيمة)
- توسيع المراقبة لتشمل منافسين آخرين غير مكعب (Amazon استُبعد صراحة من هذا المشروع بطلب المستخدم)
- ضبط `MAX_WORKERS` أو إضافة تأخير بين الطلبات لو صار حظر متكرر من مكعب بسبب حجم الطلبات الكبير

## قواعد التعامل مع هذا المشروع

- هذا المشروع **لا علاقة له** بمشروع تحليل مراجعات فروع مكعب (مستودع `Mokab_review`، الداشبوردات، تحليل الموظفين، إلخ) — لا تخلط بينهما.
- أي طلب مستقبلي بخصوص "أسعار مكعب" أو "مراقبة المنافس" أو تعديل على منطق الفحص/التنبيهات يخص هذا المستودع (`mokab-price-tracker`) حصراً.
- عند إضافة نوع تنبيه جديد أو تغيير جوهري بآلية الفحص، حدّث هذا الملف (README) ليبقى مرجعاً كاملاً ومحدّثاً.
