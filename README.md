## البنية التقنية (لماذا هذا التصميم بالذات)

- **لا يوجد Apify ولا مهمة Claude مجدولة** — جرّبنا ذلك أولاً لكنه يكلّف (Apify compute units) ويعتمد على فتح تطبيق Claude. استبدلناه بالكامل بـ **GitHub Actions** لأنه مجاني ومستقل عن أي جهاز/تطبيق.
- **لا حاجة لمتصفح آلي (Playwright) في الغالب** — اكتشفنا أن مكعب يضمّن بيانات كل منتج (الاسم، السعر) كـ JSON-LD (schema.org) في HTML الخام لأغراض SEO، فطلب HTTP عادي بمكتبة `requests` يكفي غالباً. الكود يحاول Playwright فقط كخطة بديلة إذا فشل الطلب العادي — وينتظر تحديداً تحميل DOM + ظهور JSON-LD (وليس "خمول الشبكة" الكامل، لأن بعض صفحات مكعب تبقي اتصالات شبكة نشطة باستمرار عبر أدوات تحليلات/دردشة فما توصل أبداً لحالة خمول، وهذا كان يسبب مهلة/تعليق فعلي بتشغيل سابق).
- **حماية من الإنذارات الكاذبة** — إذا رجع الفحص صفر منتجات من كل الأقسام الستة (يعني عطل بالوصول لمكعب، مو تغيّر حقيقي)، السكربت يتوقف بخطأ واضح في الـ Actions log بدل ما يفتح Issue ببيانات غير موثوقة.
- **دفع baseline المحدَّث لـ GitHub بأمان** — خطوة الـ commit تعمل `fetch` + `rebase` على `origin/main` قبل الـ `push` (مع إعادة محاولة حتى 5 مرات)، لتفادي فشل `non-fast-forward` إذا صار push آخر على `main` أثناء تشغيل الفحص (يستغرق دقائق).
- **التنبيه عبر GitHub Issues** — عند اكتشاف أي تغيير، يُفتح Issue في هذا المستودع، وGitHub يرسل بريد تلقائي (بدون أي إعداد SMTP أو أسرار إضافية). **لا يوجد تيليجرام حالياً** (تم استبعاده بطلب المستخدم).

## الملفات

| الملف | الوظيفة |
|---|---|
| `check_prices.py` | السكربت الرئيسي: يتصفح كل صفحات الترقيم (pagination) لكل مصدر، يستخرج JSON-LD، يقارن بخط الأساس، يبني تقرير التغييرات |
| `mokab_price_baseline.json` | "الذاكرة" — آخر حالة معروفة لكل منتج (الاسم، السعر، الرابط، الأقسام). يتحدّث تلقائياً بعد كل تشغيل |
| `.github/workflows/price-check.yml` | يشغّل السكربت يومياً 6:00 صباحاً بتوقيت السعودية (`0 3 * * *` UTC)، ويفتح Issue إذا لزم |

## صيغة التقرير الحالية (بطلب المستخدم — جدولان فقط، بسيطة وواضحة)

الـ Issue اليومي (لو فيه تغييرات) يحتوي **جدولين فقط**، لا فقرات نصية:

1. **💰 المنتجات اللي تغيّر سعرها** — جدول: المنتج | السعر القديم | السعر الجديد | نسبة التغيّر | الرابط. المنتجات اللي سعرها ثابت **لا تُذكر إطلاقاً**.
2. **🆕 منتجات جديدة** — جدول: المنتج | القسم | السعر | الرابط.

لا يوجد حالياً تتبّع لتغيّر الخصم/العرض، أو حالة التوفر، أو "منتج اختفى" — تم حذفها بطلب المستخدم لتبسيط التقرير (كانت موجودة بنسخة سابقة).

## كيف تُشغّله يدوياً للتأكد

تبويب **Actions** في المستودع ← **Mokab Price Check** ← زر **Run workflow**.

## إذا احتجت لاحقاً (أفكار جاهزة لم تُفعّل بعد)

- ربط بتيليجرام (بوت + chat_id كـ GitHub Secrets) بدل/بجانب GitHub Issues
- إضافة فئات/براندات جديدة (فقط أضف رابط جديد في قائمة `SOURCES` داخل `check_prices.py`)
- إعادة تفعيل تتبّع الخصم/التوفر/الاختفاء إذا احتاجها المستخدم لاحقاً (كانت موجودة، أُزيلت لتبسيط التقرير)
- رسم بياني لتاريخ السعر عبر الزمن (يحتاج تخزين تاريخي وليس فقط آخر قيمة)
- توسيع المراقبة لتشمل منافسين آخرين غير مكعب (Amazon استُبعد صراحة من هذا المشروع بطلب المستخدم)

## قواعد التعامل مع هذا المشروع

- هذا المشروع **لا علاقة له** بمشروع تحليل مراجعات فروع مكعب (مستودع `Mokab_review`، الداشبوردات، تحليل الموظفين، إلخ) — لا تخلط بينهما.
- أي طلب مستقبلي بخصوص "أسعار مكعب" أو "مراقبة المنافس" أو تعديل على `SOURCES`/التنبيهات يخص هذا المستودع (`mokab-price-tracker`) حصراً.
